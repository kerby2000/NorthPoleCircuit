## Protection/Unprotect Finding

WCHISPStudio V3.9 can still flash a CH592 through native USB Download mode after the chip is put in
a protected state, but the tested GUI did not provide an obvious way to unprotect/restore WCH-LinkE
debug attach.

Observed protected-state symptoms:

```text
WCH-LinkUtility / MounRiver:
chip type is not matched or status of chip is wrong

wlink:
Probe is not attached to an MCU, or debug is not enabled
```

Working recovery:

```powershell
# Put CH592 into Download mode.
# Temporarily bind 4348:55E0 / USB Module to WinUSB with Zadig.
$wchisp = "$env:USERPROFILE\.platformio\packages\tool-wchisp\wchisp.exe"
& $wchisp config unprotect
```

After this command, WCH-LinkUtility and MounRiver identified the chip again.

Bring-up rule: keep `Code and data protection mode` unchecked in WCHISPStudio unless intentionally
locking a final production device.

## Command-Line Gap

WCH's WCHISPTool_CMD package was downloaded and inspected.

Observed package contents:

```text
Linux: binaries, source, ISP library/header files
macOS: binary archive and library
Windows: README.md only
```

The Windows README points to the WCHISPTool setup download page. Installing WCHISPTool_Setup.exe
provided WCHISPStudio GUI tools, but no `WCHISPTool_CMD.exe` was found in the tested installation.

Until a Windows WCH-driver-based command-line executable is found or built, the production-safe USB
ISP path is GUI-only.
